Publish your portfolio.
Keep it up to date.

This is a static website: it needs no server, database, subscription, or build tools. It can run on GitHub Pages using a free GitHub account and a public repository.

What you need

A GitHub account and the extracted website folder. For everyday changes, use the included editor and upload just one updated file.

1. Put the website on GitHub

  1. Download the portfolio ZIP and extract it on your computer. Open the extracted folder. You should see index.html, content.js, editor.html, cv.html, and an assets folder.
  2. Sign in to GitHub. Select the + menu, then New repository.
  3. Name the repository YOUR-USERNAME.github.io, replacing YOUR-USERNAME with your actual GitHub username. Set it to Public, enable Add README, and choose Create repository. If you already use that repository for another website, create a new public repository called portfolio instead.
  4. In the repository, choose Add file → Upload files. Drag the contents inside the extracted portfolio folder, including assets, into the upload area. Do not upload the ZIP itself or put everything inside an extra outer folder. The repository’s first level must contain index.html.
  5. Select Commit changes. On this first upload, replace the starter README with the README from this package if GitHub asks.
  6. Open Settings → Pages. Under Build and deployment, choose Deploy from a branch. Select main and /(root), then choose Save.
  7. Wait for GitHub to publish the site; it can take up to about ten minutes. The Pages settings will show your website link. For a username repository, it is https://YOUR-USERNAME.github.io/. For a repository called portfolio, it is https://YOUR-USERNAME.github.io/portfolio/.

2. Update without editing code

  1. Open the website and select Site editor in the footer. You can also open editor.html directly from your extracted folder by double-clicking it.
  2. Use the sections on the left to change your biography, publications, projects, education, experience, links, or colors. The preview shows your draft. Use Add publication to add a paper, or Move up to change the order.
  3. Select Download updated content. This downloads a file named content.js. If your browser adds a number, such as content (1).js, rename it to exactly content.js.
  4. Open the same GitHub repository. Choose Add file → Upload files and upload your new content.js to the repository’s first level. This replaces the old file. Choose Commit changes.
  5. Allow GitHub time to publish the change, then refresh your website. The homepage and printable CV will both use the updated content. If the old content remains, try a hard refresh (Ctrl+Shift+R on Windows or Cmd+Shift+R on Mac).
The editor saves a draft, not a public update.

Editing the form does not change the live website. GitHub account access is required to publish. The editor does not ask for a GitHub token or password. Keep a downloaded copy of your latest content.js as a backup.

3. Add a photo or download a CV

In the editor, open Appearance → Choose photo. Select a JPG, PNG, or WebP picture under 5 MB. The editor resizes it and includes it in the content file, so you only need to upload content.js. Use Remove photo to return to the photo-free layout.

For a CV, select View CV on the website, then Print / Save as PDF. In your browser’s print dialog, select Save as PDF. The CV automatically uses the same profile and publication information as the homepage.

Useful fixes

The website is missing. Check that Pages is set to main and /(root), and that index.html is in the first level of the repository.

The design is missing. Check that the complete assets folder was uploaded alongside index.html.

The editor is showing an old draft. Choose Reset to website content to start from the version currently on the site. Choose Import a content file if you have a newer downloaded backup.

You want to undo an update. Upload your previous backup of content.js to GitHub and commit it.

A paper link asks you to sign in. The link opens the external publisher or repository. Availability and sign-in requirements depend on that service.
